# SoundWave v1.5.0 — Release Plan

Working plan for the next release. Keep this file updated as work lands; it is the single source of truth for what v1.5.0 contains.

## Current state (verified 2026-11-25)

- `pubspec.yaml` is at `1.4.3+8`, but the README and the latest GitHub release are still **v1.3.3 (build 7)** — code is ahead of the docs and of the APK people can download.
- Feature folders exist for `home`, `explore`, `library`, `online`, `player`, `profile`, `search`, `permissions`, `update`, `widget`.
- Tests exist (`test/widget_test.dart`, `test/test_online_music_service.dart`) but nothing runs them automatically.
- `.github/workflows/` has a build-only workflow; there is no `analyze`/`test` gate.
- Releases are signed with a **fresh debug key on every CI run**, so Android refuses to install an update over an older build. Users must uninstall, which wipes settings and downloads. This is the biggest real-world problem.

## Goals

1. Playback feels continuous and premium (gapless, crossfade, no jank).
2. Users can update without uninstalling.
3. Data is portable (backup/restore JSON).
4. Library and search stay fast with 5,000+ local tracks.
5. English + मराठी UI.
6. After a song ends, the next one is chosen and played automatically, YouTube-style.
7. The whole app feels premium: consistent motion, haptics, instant feedback.

**Non-goals:** accounts, cloud sync, social features, a backend, new music sources, rewriting state management or routing.

## Features

### F1 — Persistent release signing (do this first)

**Why:** every release today has a different certificate, so every update forces an uninstall.

- Generate one long-lived upload keystore (`keytool -genkey -validity 10000 -alias upload`), back it up in three places, and never commit it.
- `android/key.properties` (git-ignored) + `android/key.properties.example` committed.
- Wire `signingConfigs.release` in `android/app/build.gradle(.kts)` with a debug fallback so a fresh clone still builds.
- CI secrets: `KEYSTORE_BASE64`, `KEYSTORE_PASSWORD`, `KEY_PASSWORD`, `KEY_ALIAS`.
- Guard the release job: `apksigner verify --print-certs` must not show `CN=Android Debug`.
- Migration: ship a small `v1.4.4` with backup export + a "next update needs a fresh install" dialog, then let `v1.5.0` be the last uninstall anyone does.

**Done when:** two consecutive release builds install over each other, and the CI artifact is signed with the upload key.

### F2 — Gapless playback + crossfade

- `PlaybackQueue` (immutable: tracks, index, shuffle order, repeat) becomes the single source of truth.
- One `AudioHandler` owns exactly two `AudioPlayer` instances (`_active`, `_idle`), created once.
- Gapless mode: `setAudioSources([...])` over the queue.
- Crossfade mode: preload the next track into `_idle`, drive an equal-power ramp (`gainOut = cos(t*π/2)`, `gainIn = sin(t*π/2)`), then swap at `t == 1`.
- Gain layers: `masterVolume × duck (focus) × transition` — three independent multipliers.
- Fade 4 s default, clamped to `min(setting, duration/3)`, never under 300 ms; skip for tracks < 30 s and for repeat-one.
- If the next track is not `ready`, skip the fade and do a plain transition — never wait in silence.
- Handle: next/prev during a fade, pause mid-fade, seek, sleep timer, focus loss, route change, web build (gapless only).

**Done when:** an album flows with no gap, a 4 s crossfade has no loudness dip or click, and the lock-screen card never jumps backwards.

### F3 — Full-screen synced lyrics + offline cache

- Source order: sidecar `.lrc` beside the file → cache → LRCLIB → plain text → calm empty state.
- Cache raw LRC at `<app-support>/lyrics/<fingerprint>.json`; positive entries never expire, "not found" expires in 30 days; 20 MB cap.
- Parser: multiple timestamps per line, `.4`/`.40`/`.400` fractions, `[offset:±ms]`, metadata tags, unsorted input, gaps, enhanced tags stripped.
- Screen: artwork-coloured gradient, active line at full opacity, auto-scroll keeps the current line at 38% from the top, 400 ms animate, 4 s auto-follow pause after a manual drag, "Jump to current" pill.
- Tap a line to seek (`start + 50 ms`), preserving play/pause state.
- `Adjust sync ±2 s` per track, persisted by fingerprint.

**Done when:** cached lyrics work in airplane mode, the highlight lands within ~150 ms of the vocal, and the tappable seek works on a real device.

### F4 — Library upgrade: Albums / Artists / Folders + instant search

- One `LibraryRepository` + persisted `LibrarySnapshot` (JSON in app-support) so the library paints instantly and rescans in the background.
- Platform channel queries stay on the main isolate; grouping/indexing runs in `Isolate.run()`.
- Grouping rules: normalised artist keys, `albumId` preferred, compilations → Various Artists, disc/track ordering with nulls last, folders derived from the file path with the storage root stripped, duplicates collapsed by `title+artist+duration ±2 s`.
- Four tabs (Songs, Albums, Artists, Folders), album and artist detail screens, per-tab sort/filter persisted.
- Search: pre-normalised index, 250 ms debounce, 2-character minimum, ranking (exact title → title prefix → title contains → artist prefix → album/folder contains), grouped results, recent searches.
- Performance budget: library paint < 300 ms, scroll 60 fps at 5,000 tracks, keystroke < 50 ms.

**Done when:** all four tabs work from the snapshot, search feels instant, and the numbers above are measured in profile mode.

### F5 — Backup & restore

- One JSON file: settings, equalizer presets, favourites, playlists, history/stats, recent searches. No audio, no absolute paths, no artwork.
- Track identity = `sha1(normalise(title)|normalise(artist)|durationMs÷2s)` — survives reinstall and re-encoding.
- Schema: `format`, `schemaVersion`, `exportedAt`, `appVersion`, `checksum` (sha256 of canonical `data`), `data`. Accept ≤ 2 MB, reject unknown/newer versions with a readable message.
- Export via share sheet; import via file picker → validate → **preview counts** → commit atomically.
- Merge (default): union favourites, merge same-named playlists without duplicates, `max()` stats so re-importing is idempotent, settings untouched unless asked. Replace: explicit second confirmation, wipes only the listed collections.
- Missing tracks are kept as `missing: true`, never silently dropped.

**Done when:** export → reinstall → import restores everything exactly, and a corrupted file changes nothing.

### F6 — Marathi + English UI

- `flutter: generate: true`, `l10n.yaml`, `lib/l10n/app_en.arb` + `app_mr.arb`, `untranslated-messages-file: l10n_untranslated.json`.
- Plurals via ICU syntax, typed placeholders, `@description` on every template key.
- Locale provider: system / English / मराठी, persisted; unsupported device locale falls back to **English**.
- Screen order: shell → player → library → search → home/explore → settings → downloads/permissions → lyrics → update sheet → errors.
- Devanagari: line height +0.1–0.15, a Devanagari-capable fallback font, no ALL CAPS, test at 1.3 text scale.

**Done when:** `l10n_untranslated.json` is empty and nothing clips at 1.3 scale in either language.

### F7 — CI quality gate

- `flutter pub get` → `flutter analyze` → `flutter test` on pull requests.
- Add localization completeness and motion-token checks once F6/F10 exist.
- Branch protection on `main` requiring the check.
- Prove it blocks: a deliberately failing test must fail the run.

### F8 — Home-screen widget (Android)

- Native `AppWidgetProvider` + `RemoteViews`, three layouts (4×1, 4×2, 5×2) chosen on resize.
- Controls go through `MediaControllerCompat` against the `audio_service` session, so play/pause/next work **with the app killed**.
- Flutter only pushes display payload (title, artist, 256 px artwork bitmap, accent, favourite, playing state), throttled to ≤ 1/s.
- Premium look: accent from artwork, 16 dp rounded gradient background, 12 dp artwork corners, system typography, 36 dp targets, unavailable buttons dimmed to 30%.
- Progress updates only on state changes and a 30 s tick — never per second.
- iOS cannot host playback buttons in a home-screen widget; the lock screen is the equivalent there.

### F9 — Smart auto-radio (YouTube-style next song)

- Pure-Dart `RecommendationService` with an injected `Random` so tests are deterministic.
- `TrackFeatures` per track: artist/album/genre keys, year, duration, play/skip counts, last played, favourite, playable.
- Score = `0.22·artist + 0.18·genre + 0.12·album + 0.12·tempo + 0.08·era + 0.10·skipAffinity + 0.07·fresh + 0.03·popular + 0.08·explore`, then ×0.60 if the last two tracks share the album, ×0.50 if the artist already appears twice ahead.
- Pick top 3 with MMR diversity (`score − 0.25 × maxSimilarity`), accept only ≥ 0.45, else walk the fallback ladder and stop cleanly.
- Prefetch by appending to the F2 playlist (no second audio stack), recompute at 60% played, sequence ids to drop stale results.
- UI: "Up Next / Autoplay" card with a reason line, Autoplay toggle, "Not interested", skip learning.

**Done when:** a song ends and the next starts within ~300 ms with no tap, the reason is shown, and the scoring unit tests pass.

### F10 — Premium feel pass

- One token file (`lib/app/theme/motion.dart`): 100/150/250/400/500 ms, three curves, 30 ms stagger. No raw `Duration(` or `Curves.` outside that folder (enforced in CI).
- Hero artwork list → player, draggable mini-player sheet with velocity snapping, artwork scale on play/pause, cover cross-fade on track change, skeletons instead of spinners, staggered entrances capped at 8 items.
- Haptics through one `Haptics` util: `lightImpact` for play/skip, `selectionClick` for tabs/chips, `mediumImpact` for theme change; **none** on scroll or the scrubber.
- Performance: no `BackdropFilter` on scrolling content, `RepaintBoundary` around artwork, images decoded at display size, one controller per screen.
- Respect `MediaQuery.disableAnimations`.

## Definition of done for v1.5.0

- `flutter analyze` clean, `flutter test` green, CI green on `main`.
- Signed APK **and** AAB built by CI with the upload key.
